# About you: shared private-fleet profile

Settings → General now provides a preferred name and optional background. Save writes to the selected primary, so local and remote Bots workers read the same owner-scoped profile on subsequent turns. Blank fields clear the profile. Names are limited to 120 UTF-8 bytes and background to 2,000; names cannot contain control characters. No identity-provider name is inferred or copied automatically.

The internal transcript label `Owner` stays stable for existing mention routing. The executor adds instructions explaining that it is a role label, never the form of address; use the profile's preferred name naturally or a neutral greeting if absent. Profile data is JSON-encoded as user background, not authority to grant tools or permissions. This applies to runners consuming the executor's participants context, including local and supported cloud Bots runners; it does not yet personalize the separate New chat feature or unrelated coding prompts. Generated wording remains subject to model behavior.

Persistence uses the additive, idempotently created `bots_user_profiles` table, avoiding allocation of a numbered migration currently being edited by Claude. Remote read/write derives owner from the authenticated LocalHub session; clients cannot choose an owner. Remote workers do not store a second profile copy. If profile retrieval fails during execution, use empty-profile/neutral-greeting guidance rather than stopping all replies. Settings reports load/save errors and does not allow saving an unloaded form. Both primary and secondary need the new backend before this UI is usable.
