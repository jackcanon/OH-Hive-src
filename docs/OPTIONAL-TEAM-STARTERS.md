# Optional team starters

Bots → Build a team opens an optional, editable setup. Suggested team selects the nine specialists; Choose agents starts with no selections; One assistant offers a minimal start. Custom agents can be added and instructions, biography, name and built-in avatar edited. Roles are suggestions, not permission checks.

Save preset stores only editable profile drafts locally, stripping agent IDs and creation progress. Applying a preset creates fresh drafts, with no credentials, Library grants or inherited machine bindings. Profiles are created on the authenticated current Mac and use its existing local-model configuration. Host/model selection is not part of this first screen; it states this restriction explicitly. No models are downloaded, no inference is requested, and no worker is started by setup. Existing app worker behavior is unchanged.

Team progress is scoped to owner, primary endpoint and enrolled host, stored atomically under Application Support/ohhive/team-starters, with directory/file modes 0700/0600. Before agent creation, the draft is marked pending on disk. A successful ID is checkpointed before biography saving. Known-ID profile failures can resume; an unknown creation outcome is held for manual roster inspection rather than repeating a potentially successful request. This is conservative recovery, not a backend idempotency protocol. No automatic reconciliation by display name. A local advisory lock and re-read prevent concurrent/stale setup windows on this Mac from duplicating the same checkpoint. Cross-device creation is not a server transaction.

Profile retries first read the current biography. Identical content is already complete; a nonempty/revised different profile is refused rather than overwritten. New agents receive no tool policy through this flow. Tools remain separately configured in the existing inspector. Custom avatar uploads remain available in that inspector.

No migrations, FFI methods, Rust runtime, cloud runner or existing live profiles changed. New files are TeamStarter.swift, TeamStarterView.swift, TeamStarterTests.swift, plus small BotsModel/BotsView integration. Base: origin/main 5e94e87. Sif owns this branch; Loki's integration checkout was not edited.

Verification: Swift desktop compilation and five focused tests cover selected/customized recipes with stripped identities, invalid input, partial-profile retry without duplicate creation, lost-response hold across restart, and concurrent/stale setup exclusion. Full-suite result is recorded in continuity. Compilation uses a copied development FFI/bindings snapshot from the integration checkout; this is not a distributable signed app. Full fresh core/bindings packaging and installed visual verification remain necessary before deployment. No live agents were created during tests.
