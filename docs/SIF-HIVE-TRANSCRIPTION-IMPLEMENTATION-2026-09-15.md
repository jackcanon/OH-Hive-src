## What exists and what does not

`TranscribeView.swift` supports Apple speech on this Mac and a direct configured whisper.cpp server. The former stays local. The latter sends the file to the configured endpoint but creates no project/card. Its old “Hive network” label was misleading and has been corrected.

`backend/whisper.rs` can execute a speech job using a staged local `input.audio_path`. That path must be generated by the receiving worker, never supplied by a remote member as a worker filesystem path. The native `worker_start` in `ohhive-ffi/src/lib.rs` currently constructs only LlamaCppBackend. `worker.rs` runs its general draft/critique/revise text loop (except code); it does not yet execute a one-pass transcription card.

`HubClient::artifact_upload` discovers regional servers and sends the raw node key as a bearer credential to them. Reusable credentials raise attribution/impersonation concerns; Hive audio itself is intentionally shared with all members. The earlier scoped live-board ticket work does not secure this upload path. Restricting compute workers alone would not protect uploads routed to different storage operators. Additionally, GET /a/{hash} serves artifacts without authorization and with public immutable cache headers; knowing the hash is currently sufficient to read an object. Membership-gated reads would enforce invitation/removal boundaries, not conceal audio from other members. Do not require per-project confidentiality for Hive audio.

## Required end-to-end slice

1. Define a versioned speech payload containing artifact hash, declared byte length, verified media type, optional language and output format. No arbitrary remote URL or worker-local path. Use existing speech modality; transcription is one inference operation, not a text draft/review loop.
2. Add an owner/node-authenticated prepare RPC with an owner-scoped retry UUID. It atomically creates a draft project and transcription card with the immutable payload/dispatch policy and establishes the requesting member and input-upload association. A retry with changed payload must conflict. No input upload or dispatch before the user explicitly selects Hive and confirms the destination/disclosure.
3. Upload under bounded size/time limits to community storage, binding the input to authenticated uploader, project/card, hash and size. Scope transport credentials to preserve attribution without enabling impersonation. Server verifies bytes/hash and finalizes the upload idempotently. A finalize RPC makes the card claimable only after registered storage confirms the object. Clean orphaned unfinished uploads with retention rules.
4. Enforce the chosen worker policy at the hub's claim boundary, not just in a Swift picker. Match speech capability and model availability; any eligible Hive worker is allowed. All members can inspect the project, audio and transcript. Decide the owner-approved charge cap before submitting; do not reuse token-based text payouts for speech seconds.
5. Worker downloads community-visible audio to its own bounded scratch directory, validates the file/hash and invokes the configured WhisperCppBackend with a deadline/cancellation signal. Never permit audio_path, URL or filename traversal from a card. Retain heartbeat/lease-generation fencing and delete staged input on success, failure or cancellation. A lost lease cannot publish or bill.
6. Persist transcript as a community-visible artifact/card result with an authenticated executing-member/node receipt for every attempt, commit usage once with idempotent settlement, then expose progress/result through existing project polling. Retry must not create duplicate projects, duplicate transcription outputs or duplicate charges.
7. FFI exposes prepare/upload/finalize/status/cancel operations. Swift offers an explicit destination control with “This Mac” and the already-connected Hive, selects an owned project/new title, shows who can receive the file and the cost cap, then displays the project link and job state. Direct custom-server mode remains a separate destination and is never relabeled distributed Hive execution.

The destination control and upload policy model can serve Images later. Apple Speech remains local-only; this work does not offer Apple Speech to community workers.

## Verification before enabling the control

Use a disposable database and mock storage/Whisper servers first: nonmember/removed-member denial, cross-member project/input/result inspection, forged actor attribution, hash and size mismatch, path traversal, unsupported media, cancellation, timeout, lost lease, duplicate submission/finalization/completion, insufficient budget, and preservation of private-fleet isolation. Verify admin removal and retained historical job attribution. Exercise one real invited-member audio job through upload → lease → Whisper → result with explicit user-provided audio and cost authorization. Production migration reconciliation/replay remains a prerequisite for deploying the new RPCs.
