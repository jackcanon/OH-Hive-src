# Visible agent workflows from a connected Mac

A Mac connected to its fleet primary could not open the native project list, task history, execution-host picker or coding controls. Those methods called primary-local guards even though the task protocols already supported authenticated remote operation.

Project listing and task inventory now have authenticated transport reads that require verified enrollment under this authority's owner. The native bridge uses the verified selected authority for project/task/host/agent reads and existing durable coding/review/stop commands. A remote failure never opens a secondary database. Project creation and repository administration remain primary-local.

The task view places history ahead of collapsed task creation, refreshes every five seconds, names the coder and independent reviewer, and shows the current handoff and correction count. Saved file contents come from unique digest-validated frozen review packages and are explicitly labeled as saved evidence, not the mutable checkout. Results remain inspectable. A file inventory or review package never implies passed checks.

Validation: real transport test covers enrolled reads, task identity, unsigned and foreign-account denial, revoked and invalid keys. Frozen-file test preserves exact newline bytes and refuses altered or ambiguous packages. Core suite: 432 passed, one ignored fixture; bridge lint passed. Signed build, hosted review gates, installed connectivity and graphical rehearsal are tracked separately in continuity. No larger-task autonomy claim.

No project databases are copied, no fake agent chat is generated, and no inference runs on Midgaard. Execution remains on Helheim.
