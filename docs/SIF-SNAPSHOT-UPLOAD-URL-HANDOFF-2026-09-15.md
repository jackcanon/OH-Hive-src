# S-7 — shared snapshots and upload URL validation

Implemented in `supabase/migrations/20260915190000_snapshot_and_upload_urls.sql`; not deployed.

Shared snapshot project aggregation now requires `execution_mode = 'hive'` and a null deletion timestamp. Private/local projects cannot contribute titles, goals, balances or card counts to that aggregation. Existing node-key and coordinator-lease guards remain. Capacity and server summaries are unchanged.

Both upload validators now match the entire HTTPS URL with a constrained hostname/optional port and exact bucket/caller UUID path. Avatar URLs require the existing fixed `avatar` object, optionally followed by the numeric `?v=` cache version generated by the web settings page. Attachments require a single filename segment; ordinary filename punctuation and percent-encoded names remain supported. Encoded slashes, backslashes and ASCII controls are rejected. Attachment null input now fails explicitly. Membership and report ownership checks remain, and rejected updates leave stored data unchanged. No new functions or grants; CREATE OR REPLACE preserves existing ACLs.

This closes the queued unanchored-regex/script-scheme defect. It is **not trusted-origin or object-existence verification**: another HTTPS hostname with the same path shape still passes. A deployment-managed trusted storage origin and/or canonical object-key storage should be a separate follow-up, with support for custom domains and development installations. Plain HTTP development storage URLs are rejected by these validators. Current web production uploads use HTTPS.

Verification: `scripts/test-snapshot-upload-urls.mjs` runs the actual migration function bodies in a focused PGlite PostgreSQL schema fixture. Covers public/local/deleted snapshot projects, key and lease rejection, legitimate attachments/avatar versions, foreign owners/reports, nonmember calls, script/data/HTTP schemes, userinfo, prefixes, fragments, unexpected queries, newline/path suffixes, encoded separators/controls and null behavior. This is not full production schema replay or browser upload acceptance.

Before rollout, replay on a disposable copy of the production schema and test both web upload flows against its storage configuration. Refresh or invalidate coordinator and regional snapshot caches after applying the migration; previously returned/cached private data is not retroactively removed by SQL. Review existing custom_avatar_url and attachment URL rows for unsafe legacy values and remediate deliberately; this migration changes future writes, not historical data. Verify shared snapshots contain no private project IDs before reopening cached snapshot service. No production database, deployment, commit or push performed by Sif.
